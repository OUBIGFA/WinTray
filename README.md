## 简介

**WinTray** 是一款轻量实用的 Windows 开机整理工具，旨在解决开机后软件弹窗堆叠、脚本黑框闪烁的困扰，还你一个干净清爽的桌面。

核心场景：

* **窗口自动收起**：针对未提供“开机最小化到托盘”选项的软件，在启动后自动关闭主窗口，保持托盘后台运行。
* **脚本静默运行**：无窗口静默拉起 `.bat`、`.cmd`、`.ps1`、`.py` 等脚本，彻底告别命令行黑框窗口。

## 功能特性

* **托盘常驻**：系统通知区图标，支持一键打开设置和退出程序

* **受管程序列表**：可维护任意数量的程序，每个程序独立配置执行行为

* **开机自启动**：写入当前用户 `Run` 注册表项，随 Windows 登录自动启动

* **错峰启动**：按程序列表顺序依次拉起，默认间隔 3 秒；可在全局设置中调整为 0–120 秒，缓解开机集中启动造成的资源争抢

* **自动隐藏窗口**：程序列表中配置后，`--autorun` 流程触发时自动最小化并隐藏目标窗口

* **窗口检测超时**：支持 0–120 秒的可配置超时等待，应对启动慢的程序

* **关闭延迟**：每个程序可单独设置运行满多少秒后再处理窗口，跳过登录等前置弹窗（如新版 QQ）；对程序自带开机自启拉起的实例同样生效

* **重置并清理数据**：可在主窗口一键清理本地配置/日志并恢复默认状态

* **单实例保护**：防止重复启动，避免配置冲突

## 下载与使用

WinTray 仅提供**便携版**，无需安装。

前往 [Releases](../../releases) 页面，下载最新版本的 `WinTray-Portable-vX.Y.Z.zip`，解压后直接运行 `WinTray.exe` 即可。

* 配置与日志写入 `%LOCALAPPDATA%\WinTray\`，不依赖任何注册表安装项

* 不再使用时关闭程序、删除文件夹即可彻底移除

## 支持托管的程序类型

WinTray 支持添加以下类型的程序到受管列表，在开机时自动启动并处理窗口：

| 类型            | 文件扩展名           | 启动行为                          |
| ------------- | --------------- | ----------------------------- |
| 可执行程序         | `.exe`          | 默认前台启动，可选择"启动后关闭窗口"将界面隐藏到托盘；控制台程序由 WinTray 代为放入托盘 |
| 批处理脚本         | `.bat` / `.cmd` | 默认后台静默启动（不显示命令行窗口）            |
| PowerShell 脚本 | `.ps1`          | 默认后台静默启动                      |
| Python 脚本     | `.py` / `.pyw`  | 默认后台静默启动，分别调用 `python.exe` / `pythonw.exe` |

> 非 `.exe` 类型的脚本（`.bat` / `.cmd` / `.ps1` / `.py` / `.pyw`）添加时自动启用"后台静默启动"选项，且不可同时勾选"启动后关闭窗口"。

> **重要提醒**：有些软件包包含多个 `.exe` 文件，例如启动器、更新器、辅助进程和真正的主程序。添加程序时，请选择实际负责显示主界面的主程序。选错 `.exe` 可能导致程序虽然启动，但 WinTray 找不到对应窗口，启动后关闭或隐藏功能不会生效。

### 每个程序的独立配置项

* **启动参数**：为程序传入自定义命令行参数

* **启动后关闭窗口**：程序启动后自动发送关闭消息（WM\_CLOSE），多数支持托盘的应用会退到托盘而非退出；窗口消失或变为不可见都视为处理成功。对于 `syncthing.exe`、`frpc.exe` 这类没有托盘图标的控制台程序，关闭窗口会直接终止进程，因此 WinTray 会改为隐藏其控制台窗口，并在托盘中替它放一个图标：左键点击显示/隐藏窗口，右键菜单可显示、隐藏、结束托管（窗口重新显示，程序继续运行）或退出该程序。托盘图标由 **WinTray 主进程统一持有**，不会为每个程序另起 WinTray 进程。勾选“任务完成后自动退出”时，只要还有托管图标，WinTray 就隐藏设置窗口和自身图标、继续后台运行；最后一个托管结束后才真正退出。手动选择“退出 WinTray”会恢复被隐藏的窗口，再退出。删除 WinTray 前请先退出 WinTray：运行期间 `WinTray.exe` 仍处于占用状态，无法删除

* **关闭延迟**：勾选“启动后关闭窗口”后可用。程序进程启动满设定的秒数（0–600）后，WinTray 才查找并关闭窗口。适用于启动时先弹出登录窗口的程序：新版（NT 架构）QQ 的登录窗口收到关闭消息会直接退出，把延迟设置得足以覆盖登录过程（自动登录通常 15–30 秒）后，WinTray 只会处理登录完成后出现的主面板。延迟从程序进程创建时开始计算，不论是 WinTray 启动的，还是程序自带的开机自启拉起的：开机时已被自启的实例同样要运行满延迟时间才会被处理，运行已久的实例则立即处理，不需要关闭程序自带的开机自启

* **后台静默启动**：程序以无窗口模式启动，适用于命令行/脚本类程序

* **暂停任务**：持续跳过该程序的开机自动任务，直到取消暂停；仍可使用“立即启动”

### 错峰启动

全局设置中的“启动间隔”决定 WinTray 两次实际拉起程序之间至少等待多少秒，默认 **3 秒**，范围 **0–120 秒**（配置字段 `startupIntervalSeconds`）。旧配置缺少此字段时自动使用 3 秒；设为 0 取消等待，仍按列表顺序发起启动。首个程序无需额外等待，最后一个启动后也不会再多等一个间隔。

- 暂停、已在运行、校验失败或启动失败的项目不增加间隔。
- 关闭延迟、窗口检测、等待程序自带自启均在后台并行处理，不阻塞后续程序启动；已隐藏的控制台程序会及时移交托盘托管，不必等整个队列结束。
- “立即启动”不受该间隔影响。此功能是固定间隔错峰，并非按 CPU / 内存占用动态限流；重型程序较多时可调大间隔。
- **只控制 WinTray 实际拉起的程序**。已有启用的 Windows `Run` 自启项仍由系统安排，WinTray 只等待并处理窗口，无法将这些系统启动改为错峰，也不会修改其他程序的自启设置。

### 窗口匹配

WinTray 会结合进程 ID、可执行文件路径、进程名和窗口特征自动选择目标窗口，
只有达到安全评分阈值才会执行关闭或隐藏操作，不需要额外配置匹配策略。

评分系统（仅当总分 ≥ 500 时才执行操作）：

* **+1000**：进程 ID 精确匹配（由 WinTray 启动的进程）

* **+500**：可执行文件路径完全匹配

* **+250**：进程名匹配（不区分大小写）

* **+200**：启动后新出现的窗口

* **+50**：窗口标题非空

* **-80**：工具窗口（辅助窗口，跳过）

* **-60**：有父窗口的子窗口（跳过）

### 典型场景举例

| 场景                          | 配置方式                        |
| --------------------------- | --------------------------- |
| 微信 / 钉钉等开机自启并自动折叠到托盘   | 添加 `.exe`，勾选"启动后关闭窗口"       |
| 新版 QQ（NT 架构）开机自启、登录完成后折叠到托盘 | 添加 `QQ.exe`，勾选"启动后关闭窗口"，并设置"关闭延迟"（如 20–30 秒）跳过登录窗口；QQ 自带的开机自启可以保留 |
| syncthing / frpc 等控制台程序开机后台运行并可随时从托盘打开 | 添加 `.exe`，勾选"启动后关闭窗口"，WinTray 代为提供托盘图标 |
| 内网穿透脚本（frpc / ssh 隧道）开机后台运行 | 添加 `.bat` / `.ps1`，默认后台静默启动 |
| Python 爬虫/服务后台静默启动          | 添加 `.py`，默认后台静默启动           |
| 仅开机自启，不处理窗口                 | 添加程序，不勾选"启动后关闭窗口"           |

## 启动参数

| 参数                  | 说明                                             |
| ------------------- | ---------------------------------------------- |
| `--background`      | 后台启动，不弹主窗口（适用于开机自启场景）                          |
| `--autorun`         | 自动执行受管程序任务（默认由 WinTray 启动程序）                   |
| `--cleanup-restore` | 仅执行清理恢复流程：清空 `%LOCALAPPDATA%\WinTray\` 数据目录并退出 |
| `--host`            | 仅兼容旧版独立托管调用；新版不会自动启动额外托管进程 |

开机自启时，“任务完成后自动退出（托管时留后台）”的行为为：
- 没有托管图标：任务完成后真正退出。
- 仍有托管图标：隐藏设置窗口和 WinTray 自身图标，仅保留各程序图标；最后一个托管程序退出或结束托管后退出。
- 再次运行 WinTray 可打开现有实例的设置；正在操作设置或执行手动启动时，不会突然自动退出。
- 手动选择“退出 WinTray”：取消未完成的任务，恢复被隐藏的程序窗口，再真正退出。

关闭该选项则常驻 WinTray 自身托盘图标；“启动后最小化到托盘”决定这种常驻模式下是否显示主窗口。

## 常见问题

**Q：程序运行后没有主窗口怎么进入设置？**
A：右键系统托盘中的 WinTray 图标，选择“打开设置”；如果自动退出模式下只剩受管程序的图标，重新运行 `WinTray.exe` 即可打开设置，不会创建第二个主进程。

**Q：开机自启生效后如何取消？**
A：在设置页取消勾选"开机自启动"，程序自动清理对应的注册表项。

**Q：新版 QQ 开机后没有折叠到托盘，反而登录失败或直接退出了？**
A：新版 QQ 启动时先显示登录窗口，此时收到关闭消息会直接退出。为该程序设置"关闭延迟"，让延迟覆盖整个登录过程（自动登录通常 15–30 秒，手动登录请预留更长时间）。无论 QQ 由 WinTray 启动还是由它自带的开机自启拉起，WinTray 都会等它运行满延迟时间、主面板出现后再收起。

**Q：QQ 自带开机自启和 WinTray 同时启用，会不会双开？**
A：WinTray 会检查直接指向所配可执行文件的 `HKCU/HKLM Run` 自启项（含 32 位项），并尊重任务管理器中的禁用状态。发现启用项后，只等待系统启动该程序，最多等待 120 秒；发现进程后再按“关闭延迟”处理窗口。超时会记录明确日志，**不会补启动**，避免系统稍后启动造成双开。“立即启动”仍可手动启动未运行的程序。本检测不涵盖任务计划、启动文件夹或第三方启动器的间接自启，也不会修改其他程序的自启设置。

**Q：加入列表的程序没有被自动最小化？**
A：确认该程序配置了"自动隐藏窗口"选项，且 WinTray 是以 `--autorun` 参数触发的（开机自启时由系统自动传入）。如程序启动较慢，可适当增大超时等待时间。
